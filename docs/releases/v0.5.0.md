# v0.5.0 — Executable Governance Experiments

Trust Protocol Interop Lab v0.5.0 advances the repository from governed standards intelligence into a broader executable-governance and interoperability-assurance workbench.

The release captures a coherent post-v0.4.0 tranche in which architectural and governance propositions are represented as bounded Interop Cases or experiments with declared authority boundaries, machine-readable invariants, deterministic scenarios, reproducible evidence, explicit maturity states, and visible residual limitations.

## Release proposition

> The Lab can turn consequential governance and interoperability propositions into bounded, falsifiable, executable compositions without converting successful execution into unsupported claims of authority, conformance, certification, or production readiness.

## Highlights

### Agent Relationship Architecture

`IC-ARA-REL-001` progressed through the minimum executable relationship programme with pinned baselines, reusable-component mapping, relationship-state and lifecycle evidence, adversarial pressure testing, standards-boundary review, and explicit promotion gates.

Its **Interoperability Tested** claim remains bounded to the repository's executable semantic-composition reference model. It does not claim blanket TSP, VTA, RCard, VRC, production-security, legal-effect, or external-certification conformance.

### Evidence-gated maturity

The Lab now applies stronger evidence requirements to maturity promotion. Interoperability Tested cases require a governed evidence manifest with a bounded claim scope, reproducible runner, passing result, repository-contained evidence artifacts, and integrity binding.

Missing or insufficient evidence does not become a pass, and case inclusion in a release does not itself promote maturity.

### Dual-Path Actuation Control

`IC-DPAC-ACTUATION-001` establishes an **Experimental** executable model for the DPAC non-collapsibility property: consequential actuation requires simultaneous current action-specific authority and a separately administered capability envelope at the actuation boundary.

The case records seven explicit invariants, falsification scenarios, deterministic execution, fail-closed/indeterminate handling, and explicit limitations.

A subsequent DPAC × GovOps delegated-loan pressure test exercises authority revocation between authorization and actuation, capability-revision TOCTOU, target substitution, amount widening, and duplicate/retry execution.

DPAC remains Experimental. The repository does not claim OS, container, cloud, hardware, or organizational independence unless separately evidenced.

### GovOps executable-trust composition

The GovOps composition work makes authority, policy decision, capability, enforcement, runtime effect, and evidence separately observable while preserving the boundary that a successful technical or policy evaluation is not itself authority to act.

### ANAB × DCAS named-agent assurance

The release includes the merged bounded ANAB × DCAS assurance experiment from PR #120. Six deterministic scenarios exercise PASS, FAIL, and INDETERMINATE outcomes, including stale evidence, revoked state, missing evidence, overclaiming, and absent action-specific authority.

ANAB retains authority for named-agent requirements and evidence semantics. DCAS retains authority for evaluator-contract/result semantics. Interop Lab owns only the execution evidence and local maturity judgment. Identity or name assurance MUST NOT be interpreted as action-specific authority.

### Case-estate adoption and readability

The case estate now exposes a consistent newcomer-facing contract covering purpose, concrete scenario, current resolution, maturity, evidence produced, and remaining uncertainty. CI enforces that documentation contract so case discoverability and claim boundaries cannot silently regress.

### Repository assurance and publication

The release baseline retains deterministic repository assurance controls, including case/catalog validation, evidence validation, generated-tree cleanliness, link checking, executable experiment checks, and the GitHub Pages build as publication evidence.

## Claim boundary

This release is a versioned repository and evidence baseline. It is **not** a blanket certification or maturity promotion.

Specifically, v0.5.0 does not by itself establish:

- production security;
- external or independent certification;
- legal authority or legal effect;
- wire-protocol conformance;
- standards-body endorsement;
- independent implementation;
- organizational or physical control-plane independence; or
- interoperability beyond the exact bounded claims recorded for individual cases.

Experimental and Candidate cases remain Experimental and Candidate after release unless their authoritative catalog state separately changes through evidence-backed promotion.

## Governance boundary

Authority remains with the owning specification, governance source, or repository for each semantic claim. Interop Lab owns its local composition, execution evidence, maturity judgment, and publication record only.

The following invariant continues to apply:

> Discovery is not dependency. Mapping is not endorsement. Verification is not authority. Cryptographic validity is not a relying-party trust decision. Successful execution is not permission to act.

## Deliberately excluded

The open grouped major GitHub Actions dependency update in PR #114 is not part of the v0.5.0 baseline. Major dependency changes remain separately reviewable and should not be pulled into a release solely for convenience.

## Validation expectation

The release-prep PR must pass the repository's required assurance and publication checks before merge. The final release tag must point to the protected `main` commit produced by that merge.
