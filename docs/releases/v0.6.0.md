# Trust Protocol Interop Lab v0.6.0 — Current Implementation Evidence & Semantic Preservation

**Release date:** 2026-09-13

## Summary

v0.6.0 is the largest evidence-oriented Lab release since the executable-governance baseline. The Lab now carries a substantial body of source-pinned current implementation evidence for VTI/OpenVTC and composed application cases, while preserving a strict distinction between what a target actually demonstrated and what remains a normative, deployment or multi-implementation evidence gap.

## Current implementation evidence

### Resolved-effect binding

Bounded evidence demonstrates that the effect attributed to an authorized operation can be tied to the exact exercised request/decision path rather than inferred from an unrelated state change. This is evidence for the exercised surface, not a universal transaction-integrity claim.

### Credential issuance replay convergence

The release packages target-native replay/convergence evidence for credential issuance behavior. Repetition and replay are treated as lifecycle semantics that must converge correctly rather than merely as transport retries.

### VAC use-time authority

The Lab exercises the distinction between possessing/presenting an authorization credential and checking whether authority is current at the time an action is attempted. Where live status/current-authority evidence is unavailable, the residual remains owned outside the bounded passing experiment.

### Personhood and transport equivalence

Current implementation evidence can compare personhood-related behavior across exposed transports. Equivalent-looking messages are not assumed to preserve equivalent semantics unless the observations support that conclusion.

### Trust Task / credential paths

Trust Task and credential composition is exercised as an end-to-end implementation path, preserving the distinction between task lifecycle, credential lifecycle and current authority.

## Data Rooms and OpenVTC

The release includes current target-native evidence for Data Rooms and adjacent policy/status/task surfaces. The evidence advances propositions presently supported by the implementation. It does not manufacture evidence for private-room ZK behavior, same-subject/common-control semantics, witnessed anchoring/freshness, migration, operator-control or independently meaningful two-implementation portability where those surfaces do not exist.

## Vetted-admission evidence

The current vetted-admission probes make observer, persistence and evidence-family boundaries explicit. They exercise active persona/target community, discovery, directory/profile, status/policy, application state and retained identifier surfaces where target-native execution exists. DPIP remains the owner of the resulting privacy judgment.

## Protected delegated care

The protected delegated care case now has broader executable evidence for current authority, prescription/refill lifecycle, refill-disclosure comparison and runtime privacy. The case remains experimental and does not claim production healthcare fitness, clinical correctness or legal authorization.

## Evidence and governance boundaries

v0.6.0 preserves these rules:

- upstream remains authoritative for normative semantics;
- evidence is pinned to target revision, case and observer surface;
- synthetic/calibration evidence is not target runtime evidence;
- an executable PASS is not blanket interoperability certification;
- the Lab does not promote RAHP or DPIP terminal states;
- absent genuine independent implementations remain deferred evidence rather than synthetic closure.

## Coordinated release

This release is coordinated with RAHP v2.3.0 and DPIP v0.2.0. The Lab provides bounded evidence; DPIP evaluates privacy-specific propositions; RAHP reconciles assurance state and residual ownership. The three version numbers remain independent because the repositories have different governance and compatibility authorities.

## Upgrade / use guidance

Consumers should pin evidence to the v0.6.0 tag when citing the release baseline. When an upstream specification or target implementation changes materially, rerun only the affected cases/evidence producers and preserve lineage to the previous evidence rather than overwriting historical results.

## What remains open

Genuine implementation portability/substitution, some private-room/common-control semantics, deployment-level observer evidence and other externally gated propositions remain intentionally open or deferred. They are not release blockers when their ownership and reassessment triggers are explicit.
