# Repository and Artifact Status

## Repository status

**Experimental / incubation**

This repository contains independent, standards-adjacent interoperability work. It is intentionally positioned between informal design discussion and upstream standardization.

## Status vocabulary

| Status | Meaning |
|---|---|
| Exploratory | Early analysis; problem and boundaries may still change |
| Experimental | Coherent design exists; implementation or validation is incomplete |
| Candidate | Stable enough for structured review and interoperability work |
| Interoperability Tested | Exercised by implementations/test vectors with recorded results |
| Proposed Upstream | Submitted to or formally discussed with an upstream project |
| Upstreamed | Accepted or incorporated upstream |
| Superseded | Replaced by a newer artifact or upstream specification |

## Status rules

- Status applies to each artifact, not automatically to the repository as a whole.
- A candidate artifact is not a standard.
- Upstream specifications remain authoritative.
- A change in upstream behavior should result in a new artifact version or an explicit compatibility note rather than rewriting historical baselines.
